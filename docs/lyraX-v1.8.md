# LyraX v1.8：可靠数据、研究验证与日常跟踪

日期：2026-10-10（Asia/Shanghai）。状态：**P0–P5核心工程交付完成**。用户后续已授权实施；当前功能、最终证据及外部条件见[V18-DELIVERY](V18-DELIVERY.md)，使用见[V18-USAGE](V18-USAGE.md)。以下保留规划依据及范围约定。

依据：[原始目标](../GOAL.md)、[v1.5交付](V15-DELIVERY.md)、[交付后设计审计](V15-DESIGN-AUDIT.md)。v1.8继续使用Python、pandas/NumPy、bt/ffn、Streamlit、Parquet、SQLite、Conda；不引入第二个回测框架或后台数据库服务。

## 1. 版本目标与边界

v1.5已实现六类策略及手动研究/跟踪链路。v1.8将重点转向三个用户问题：

1. 各用途的数据是否选对，日常更新和并发操作是否可靠？
2. 历史结果能否还原，换时期、提高成本后表现是否稳定？
3. 每月应做什么，计划与实际执行有哪些差异，受阻时如何处理？

交付主线为：**修复D01/D02 → 数据用途统一 → 可还原研究归档 → 分段与成本验证 → 执行复盘和运行诊断 → 完整验收**。

- 核心范围：单机、单市场XNYS、单币种USD、每个隔离环境一个账户；日线、月度、只做多、无杠杆、人工执行。
- 延续demo/paper/real隔离、空真实账户、真实事件凭据、资金/份额预留和对账门槛。
- 保留六个策略模板。新增模板不作为本版完成条件；自动搜索参数、机器学习、任意Python策略上传、多策略争用同一账户、多市场、多币种和自动交易均不纳入核心范围。
- 真实基本面和真实执行原价来源的资格单独验收。可以完成CSV/离线工程，但不能以此宣称真实前向或实盘接入完成。
- 本版不安装外部通知或定时服务、不购买数据；提供本地运行入口和可审阅的配置样例。实际启用服务和真实账户选择需届时明确。
- 完成判断依据正确性与复现证据，不设置收益率门槛。真实前向表现需要时间累计，不阻塞独立的工程交付。

## 3. 数据用途与并发发布：先修根因

### 3.1 分开“系列”“快照”“用途”

- **系列series_id**：来源、市场、币种、明确标的集合、价格/因子口径、字段定义及版本的稳定身份。改来源或口径建立新系列；更新日期不改变系列身份。
- **快照snapshot_id**：某系列一次完整、不可变的内容版本。沿用现有内容哈希，不覆盖历史。每次抓取的尝试和实际收到时间另记。
- **用途绑定**：账户/工作区显式选择signal、execution、valuation、factor各用途的系列；绑定有修订号和生效范围。valuation可显式复用合格execution系列，不能回退到任意latest。
- **解析结果**：一次任务使用的不可变DataBundle、各用途系列版本、日历/单位/资格、所需时间覆盖和检查结果。对账和报告能够复用该结果，不能各自再读取不同的全局latest。

同一快照确实同时满足研究和执行条件时可复用，但必须通过两种用途各自的检查。价格缺失不填零，执行原价缺失不使用复权价替代。

### 3.2 统一解析入口与消费矩阵

| 入口 | 必须选择的输入 | 关键规则 |
|---|---|---|
| 历史研究/分段验证 | signal、factor（按策略要求）、冻结日历 | 完整预热与共同决策网格；报告冻结精确快照 |
| 当前信号 | signal、factor、当前实际时钟及绑定策略 | 使用生成时已收到/可用数据，月末和有效期规则保持 |
| 新计划/修订/通用CLI plan | 信号原归档 + execution + valuation + 账户版本 | 新报价只影响数量/复核，不能改写冻结权重或另建同月意图 |
| 模拟成交/公司行动 | 执行日期原价、行动凭据、旧计划冻结配置 | 事前数量上限不变；拆股前后单位一致，缺价不成交 |
| 账户报告/导入预检/对账 | valuation、持仓及核对时点 | 覆盖目标与实际持仓；按指定历史时点取价，不用当前价对历史账单 |
| daily | 先更新各已绑定系列，再冻结各阶段输入 | 后续环节显式接收对应引用，不用导入顺序决定选价 |

原价可以只有近期数据；若价格质量检查、存量计划或对账需要更早价格/行动，列出缺少区间。研究预热长度只由研究系列满足。各来源日历不要求内容哈希相同，但市场、相关交易日和实际收盘时点必须一致，覆盖预热、有效期和结算所需交易日。

日常任务冻结的是**本次实际解析的输入**，用途绑定指向的是会更新的系列。下次任务需重新核对新鲜度，不把第一次解析的快照永久当作最新数据。修改用途绑定不会自动改变旧信号/计划的历史引用；跨来源切换须明确核验，不静默选择另一供应商。

### 3.3 并发与失败恢复

D02先在存储层修复，保证CLI、UI和直接调用同样受保护：

1. 取得稳定的文件锁，再读取当前版本、核对来源、合并记录、校验首次收到时间并发布；下载在锁外完成。最初采用单机串行写入，不为几只ETF增加队列服务。
2. 同内容批次重复提交返回同一快照；同ID不同内容拒绝。已有内容目录必须校验，不能因目录存在就当作成功。
3. 用临时目录写入并验证完整文件，再发布不可变目录和目录登记；索引提交后更新兼容指针。中断后的孤立目录可校验后补登记，损坏产物不发布。
4. 因子、价格增量、CSV导入、研究报告发布和备份使用约定一致的发布保护。原先SQLite事务不能代替文件合并锁。
5. 锁顺序冻结为“需要的任务/维护锁 → 共享发布锁 → 短SQLite事务”。禁止持SQLite写事务再申请文件锁；禁止在发布锁内下载、运行bt或等待子进程。只读不可变文件不需要持写锁。
6. 备份持相应维护/发布锁并保留SQLite data_version及文件校验；其他账户事实发生变化时拒绝发布或有限重试，不能把备份锁描述成阻止所有数据库写入。
7. 首版本地合并在锁内完成；若数据量使锁时间过长，再改成锁外准备+代数版本复核+有限重试。不能用未经验证的乐观合并替代D02验收。

P0必须核对现有daily、research、submission、备份和迁移锁的调用顺序，形成锁表及反向获取回归。进程退出由OS释放锁；不能按超时删除存活进程的锁文件。

## 4. 可还原的研究归档

P0在任何业务改动前，先按白名单归档当前v1.5源码及锁文件，并对照原运行指纹；这份基线不能等到P2才保存。新研究应在提交时冻结可还原源码依据，执行前后核验一致；运行期间代码变化则阻断发布，不能事后用修改后的工作树补造来源。

新增按需导出的本地研究包，内容包含：

- 原始冻结实验、策略/参数/费用/时间约定、精确价格/因子/日历快照和完整报告。
- 对应源码文件、项目安装声明、已验证依赖锁、解释器/平台信息、逐文件SHA256、包格式版本及构建清单。
- 已有Git提交时记录提交及工作区差异；无提交或工作区有修改时按明确白名单保存实际源码。不能只记录HEAD或哈希，也不能只打包Git已跟踪文件。
- 运行源码指纹与归档源码必须一致。旧运行若缺失原源码，标为`SOURCE_UNAVAILABLE`，禁止用当前代码冒充旧实现导出。
- 支持输入完整性校验和新空目录恢复；已有Conda锁支持同平台重建，安装需要的离线包缓存是否包含单独标记。

白名单以`src/`、`pyproject.toml`、依赖锁及必要启动文件为主；样本/配置只收录此次运行的明确依赖。密钥、环境文件、真实券商原始文件及其他运行目录不自动打包。数据来源和使用限制随包保存，本地导出不代表获准公开分发。

恢复与重算分开：校验/解包不执行归档代码；用户显式调用研究重算命令时在独立目录和兼容环境运行，只重算研究，不载入真实账户写入入口。原实验身份保留，新重算生成独立attempt并关联原运行。相同锁与平台应获得相同信号/交易和数值；允许的浮点差异阈值须在测试前固定，不能事后放宽。

本版保证同一已验证Linux/WSL环境的源码与输入可还原，不承诺跨平台二进制一致。没有旧源码的历史报告仍可读，但不能宣称完成旧版本重算。

## 5. 研究验证套件：扩展研究能力

### 5.1 分段表现与成本压力

新增验证套件，复用现有bt引擎和六模板：

- 固定规则、固定标的篮子、明确基准、预先指定若干不重叠评估窗口。
- 每个窗口具有完整预热；预热数据只用于指标，不计入该窗口收益。每个独立窗口从相同初始现金开始，先等到合格月末，再按现有次日收盘约定成交。
- 独立窗口净值不拼成可投资的连续净值，也不把年化收益相加。汇总显示各窗口结果、费用、换手、样本长度及受阻原因。
- 另提供已有连续回测的年度/阶段切片；切片保留原持仓，必须与独立重启窗口明确区分。
- 成本场景默认可选基准、佣金/滑点各2倍、各3倍，固定费用也按明确参数处理；用户在运行前确认场景。这是敏感性分析，不代表真实券商报价或概率预测。
- 成本变化可能因现有费用预留机制改变实际虚拟数量，需重新运行bt，不能从原净值机械减去费用差。

每个同窗口/同场景内部，基准和候选条件一致。跨费用场景、跨区间的图表标为敏感性分析；不能放宽现有`compare_runs`严格可比门槛后混排“赢家”。不做大规模参数搜索、不自动选择账户策略；不声称固定规则的分段回测是经过训练选模的walk-forward。

### 5.2 先登记研究约束，再生成证据

引入不可变研究协议，保存模板版本、篮子、参数、基准、窗口、费用场景、关注指标、用途、代码版本及登记时间。

- 已观察历史只能标为探索/验证，保留当前约束。
- 支持登记未来评估/纸面观察计划。起点须晚于登记实际时间，且有足够预热；修改规则建立新协议并注明原协议结束原因。
- 未来行情尚未到达时显示`WAITING_FOR_DATA`。真正的前向信号须在原业务时点归档；以后取得历史价格做重算仍属于历史重建。
- 前向监控协议选择独立paper工作区；演示固定时钟仅验证工程，不进入真实前向证据统计。
- 每次评估显示参数变更/协议中止/漏跑情况。系统只能记录本项目中的使用与登记，不能证明用户在其他地方从未看过数据。

### 5.3 套件执行与发布

套件规格、全部子实验键和数量在提交前冻结。首版建议默认27个以内成员回测，硬上限48个；例如3成员×3窗口×3成本=27。超限明确要求缩小范围，不静默删项。

一个本地工作进程顺序运行子实验，沿用现有attempt与报告发布逻辑。套件父记录不占用子实验的唯一活动attempt约束；提交和恢复需有唯一套件执行权，不能让手动任务插入后造成双执行。已有成功子项校验后复用，失败子项显式重跑并保留历史。

任一必要子项缺失/失败时，总报告为`INCOMPLETE`；可以查看已完成结果，但不计算误导性的完整汇总。断电重启从确定提交点恢复，不能重记账户事件。

## 6. 执行复盘与人工操作

在现有调仓计划页增加只读复盘和CSV导出：

- 并列显示目标权重、各修订建议数量、明确关联的实际成交数量、未完成数量、实际持仓、费用和对账状态。
- 按plan_id/修订及明确事件关系汇总；无法关联的成交列出待核实，不按近似价格/日期自动匹配。
- 冻结参考价与成交价的差额：买入为`数量×(成交价−参考价)`，卖出为`数量×(参考价−成交价)`，正值表示相对参考价成本增加。缺少同单位参考价时不可计算。
- 部分成交、多笔费用、冲销/更正和晚到成交使用有效事件版本；拆股先转换到一致单位。费用另列，不能再次写入账本。
- 日线参考价差只能称“相对参考价差额”，不宣称为精确券商滑点或完整执行成本归因。
- 结算等待、费用预留、整数份额和现金缓冲造成的目标偏离显示独立原因；计划外成交及超出建议的实际成交保留事实并提示核对。
- 导出含plan_id、revision、生成时间、参考价时间、有效期、检查结论、来源类型和逐项原因。下载前从数据库重查当前状态；历史导出明确标注历史版本，不能把过期导出当作当前可执行建议。

账户总览可增加所选期间的“期初权益、期末权益、净入出金、投资盈亏变化”核对表。内部交易/分红不能再次当外部资金流；没有可靠估值时显示不可计算，不新增未经验证的精确TWR或税务成本法。

## 7. 日常运行诊断与中文界面

保留四个主页面，增量增加选项卡/展开区，不重建前端：

| 页面 | v1.8新增能力 |
|---|---|
| 账户总览 | 行情/凭据/对账就绪状态、期间投入与盈亏核对、待处理事项入口 |
| 策略研究 | 数据系列选择及用途资格、可还原包导出、协议/分段/费用套件及不完整状态 |
| 调仓计划 | 显式两个价格用途、计划导出、修订与成交偏差复盘 |
| 运行状态 | 环境doctor、各用途更新时间、任务覆盖/漏跑、恢复动作、备份状态和本地提醒 |

新增只读doctor：检查解释器/安装依赖、配置、数据库版本、数据引用、所需历史覆盖、价格资格、执行/对账条件和报告完整性。诊断不得自动创建空账户、迁移数据库、修正数据或解除风控。

本地提醒使用稳定键去重，记录首次/最近发生及当前状态。确认已读不等于解决；新一轮相同事件可增加发生记录而不重复生成计划。例：数据过期、任务失败、缺月末信号、计划临近失效、对账差异、应有备份未完成。

任务健康按市场日历与发布延迟判断；休市、尚未收盘、有效全现金月和无交易需求不是失败。区分未安装调度、已安装但没有运行证据、已实际运行。服务重启只恢复持久状态，不自动补造过去信号。

提供CLI与Linux/WSL调度模板、工作目录/环境诊断和日志轮转说明。模板安装为后续显式操作，默认仅生成到项目目录。v1.8核心提醒只在本机看板/CLI展示；邮件、IM、外部Webhook需要渠道和发送授权，列为可选扩展。

## 8. 架构、迁移与兼容

### 8.1 最小新增职责

### 8.2 迁移约定

- P0先在临时库验证schema v3→v4增量迁移和回滚，P1再迁移隔离实际工作目录；迁移前完整备份并核验无活跃发布。
- 现有v1/v2信号、v1.5研究规格和报告保持可读；新增规格采用明确schema版本，不静默把旧哈希重算成新格式。
- 旧快照可登记为legacy系列，已有引用/manifest保持原样；无法唯一确定用途时标为`UNASSIGNED`，要求显式绑定，不能猜测数据资格。
- v1.5旧latest只用于明确的旧兼容路径；新v1.8任务依赖目录登记和用途绑定。新旧写入入口全部接共享发布保护，避免留下旁路。
- 新程序拒绝损坏/未来schema；升级后的工作区不可交给旧程序继续写。回退通过恢复迁移前完整包到新空目录，不执行破坏性降级。
- 新格式备份包含数据系列及全部角色快照、因子、协议/套件、归档清单、提醒和旧引用。源码包与研究依赖可选择随完整包携带，是否可重算明确标记。
- 缺文件、哈希损坏、跨环境路径及未发布产物都不能成为可恢复成功；源目录不断变化时清晰失败，保留原包。

## 10. 关键验收矩阵

| 场景 | 独立预期 |
|---|---|
| D01跨源日常闭环 | 长历史研究快照+短期原价，调换导入顺序仍产生同一策略权重/正确真实单位数量；CLI/UI/daily一致 |
| 角色数据故障 | 原价过期只阻断相关执行/估值；研究可查看。研究历史不足只阻断信号；已有事实导入仍可记录 |
| D02并发不同批次 | 初始4行，两进程各增加1行，成功后最新6行；冲突ID整体拒绝；首次收到时间不被重写 |
| 并发相同批次/增量 | 同快照幂等，最新版本不回退；日期重叠修订、缺行和来源切换按契约处理 |
| 发布/备份中断 | 每个目录/登记/指针边界中断后无半发布成功；恢复引用闭合；已有账户事件不重复 |
| 策略与账户兼容 | 同冻结输入fixed/trend及六模板数值不意外改变；旧计划继续引用旧规格和预留 |
| 归档复算 | 原实现归档后修改当前工作树，在新空目录用原代码+数据重算，信号/成交和约定精度内数值一致 |
| 分段边界 | 预热不计收益；首月信号/次日成交正确；独立窗口从相同现金出发且不伪造拼接曲线 |
| 成本场景 | 固定可手算路径验证费用；同场景基准公平。再平衡数量会变时不简单断言所有较高费用净值必然逐日更低 |
| 套件中断/重跑 | 已成功子项不重复；任一必要子项失败则父报告INCOMPLETE；总数上限不被绕过 |
| 研究协议 | 登记后变更形成新版本；未来区间等待数据；历史重建不被标为当时已归档前向记录 |
| 实际执行偏差 | 买卖符号、部分成交、费用、修订、拆股、冲销、未关联记录按人工小样本核对；仅展示不写账 |
| 日历及提醒 | 周末/节假日/提前收市/夏令时正常；NO_ACTION不误报漏跑；确认提醒不解除对账阻断 |
| UI/跨环境 | 四页真实浏览器可操作；多标签/刷新/重启不重复提交；demo测试因子和模拟资金不能进入real |

## 11. 可选扩展池及启动条件

以下不阻塞v1.8核心交付；用户选定后再形成小任务及独立验收，避免一次扩大版本。

| 扩展 | 可以带来的能力 | 前置条件与边界 |
|---|---|---|
| 双动量/防御资产轮动模板 | 相对排名+绝对趋势门槛，明确防御标的或现金 | 冻结规则及参数、合格数据、与六模板共享接口；不根据回测挑参数 |
| 标准账单字段映射向导 | 保存列名、日期、费用、事件ID映射，减少每次手工转换 | 至少一份脱敏券商样本；不猜结算/费用重复关系；真实格式需真实样本单独验收 |
| 合格基本面来源适配 | 在价值/质量规则中使用真实时点数据 | 来源权限、定义/修订/首次收到证据、证券适用性；不能凭ETF合成因子通过 |
| 独立影子组合比较 | 在不改真实账户的情况下连续观察其他策略 | 每组合独立paper工作区及真实原价/行动；先定义比较资金流和开始时间，不让多策略争用单账户 |
| 多策略组合配置 | 把几个策略目标合成一个账户最终目标 | 单一资金/预留所有者、冲突和预算分配、组合版本及月末规则另行设计；建议后续版本 |
| 外部运行通知 | 失败或待办发送到指定渠道 | 明确接收方、凭据及发送授权、重试/去重；本轮不发送任何消息 |
| 券商只读对账 | 获取成交/现金/持仓用于对账 | 明确券商及只读接口权限；不包含交易权限，也不自动推断可下单 |
| 自动交易V2 | 官方或成熟适配器、模拟券商订单及故障恢复 | 另行明确请求、市场/券商/API条件；继续遵循GOAL的V2启动门槛 |

不在本版推进高频、做空杠杆、期权、机器学习、动态历史成分股池、多币种税务或云端公开部署。固定ETF篮子的研究不能宣称解决了全市场幸存者偏差问题。

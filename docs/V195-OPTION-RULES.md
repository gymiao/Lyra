## 信用价差研究规则（已实现，完整计划/资格尚未验收）

- bull_put_credit_spread：卖OTM Put，买同行权到期且更低行权价Put；先建立长腿。短腿按原put_moneyness规则；长腿需显式最小宽度minimum_spread_width，取满足宽度最近合约。
- bear_call_credit_spread：卖OTM Call，买共同到期且更高行权价Call；先建立长腿。短腿按原call_moneyness规则；长腿同上，向上选择。
- 每包各1张，同标的/到期/乘数/交割物，净信用须为正且小于价差宽度×乘数。佣金后净收益、理论最大亏损分开列。
- 买ask、卖bid、逐腿费用；不把未成交短腿权利金当成可用现金。Put保守预留短腿全部履约现金；Call需核验长腿更高执行价的行权现金与短腿指派负股中间状态。长Call可保护更低执行价的短Call，但预留长Call完整履约现金；发生临时负股仍标记异常，不能因后续相抵抹掉该状态。未验证资格保持阻断，不凭理论有限亏损释放担保。
- 先保护腿，再短腿；退出先短腿、再长腿。任一部分成交失败保留当前事实/暴露，重新检查剩余资源，禁止回滚已发生的事实。

## 滚动和Wheel规则（原生与工作区分批实现，完整准入未完成）

- rolling_put/rolling_call/rolling_collar：只在明确月末周期平旧、处理履约和T+1结算后复核覆盖/现金再开新；保留原有股票篮子，不能以每月全平股票替代持续持股规则。
- Wheel：CASH → 现金担保Put → 未指派回现金，指派且结算完成进入STOCK → 足额备兑Call → 未指派保留STOCK，指派卖股且结算完成回CASH。状态来自实际模拟账本事实，不由目标计划或假设指派切换。
- 信号冻结、计划/预留、成交、结算、阶段检查与报告分别持久化。退出失败、缺报价、资金不足、未知公司行动暂停；恢复核验事实与阶段身份，重跑不重复开仓或交割。
- 长Put到期实值而缺覆盖股份时，必须通过明确且可验证的事前退出或异常处置政策；不能假定自动现金结算。长期限买Call实值自动行权也需完整资金检查。

本文件不提供新增模板执行资格。资格与支持矩阵只在每项生命周期、独立资金核对、恢复和当前源码证据通过后更新。

## 原生研究的显式到期处置政策

final_lifecycle=natural_expiry保留原自然交割行为。新增natural_expiry_with_delivery_exit需要完整合成执行路径：到期日收盘前20分钟检查当前同步报价/持仓；实值长Put缺覆盖股份，或实值短Call缺股份且相应实值长Call不能交割足量股份时，以MOC退出该腿，按买ask/卖bid及逐张费用记账。若短Call和足额保护Call都实值，先明确行权长Call取得实际交股凭据，再等待短Call指派；行权/交割费用为本机械模型显式0假设，不代表券商费率。其余腿按官方自然到期/交割；恢复日只处理真实交割得到的股票，不虚构现金结算。缺报价或退出失败停住，不以终值理论替代。

该政策是显式研究假设，非券商自动行权承诺；实际MOC成交、到期收据和账本分别核对。正验证无价值到期、实值Call、未覆盖Put及Call价差到期价格落在两行权价之间的路径。未接入统一工作区前缀/READY计划，不表示新增模板完成第10.4节。

前缀自然估值截止为该日后的纽约本地午夜。LEAN辅助退市事件需枚举下一个可交易日期，前缀不提供此日期后的价格、禁止估值截止后的下单并拒绝超时事件；只记录官方事件的原时间，不伪造提前到期。工作区仅接受一份冻结请求，不绑定ETF成交缓存。

1.95.2将共同行权价距离按同价合约报价的平均距离计算，避免合约ID数量改变最近行权价；这是结构正确性修复，不是收益调参。

## S6 原生故障场景规则（2026-10-16，观察结果前登记）

- 合成前缀可显式指定assignment_scenarios：合约ID、交易日、正整数张数。仅标准美式空头，当日确实价内时由LEAN公开IOptionAssignmentModel返回数量，LEAN自身履约/交割，不向账本伪造指派；不是指派概率模型。
- 每合约最多一条，数量不超过冻结空头；日期须在开仓之后、退出及到期之前。前缀只传已知合约、不晚于截止日的场景；完整世界身份仍绑定原输入。
- 部分Put指派保留剩余义务，不开始Call。滚动Call/Collar交股后下周期覆盖不足停止，不补买；成功前缀不回滚。原生事件逐笔落盘，失败保留凭据，不发布成功报告或把未经核验事件写入主账户。
- 未知公司行动走待核实凭据入口，阻断原生执行；拆股/零碎股保持实际精确数量，不为Wheel凑整百股。场景不证明真实数据或指派时刻。
- 首次原生验证暴露固定LEAN BacktestingBrokerage的行为：GetAssignment返回数量只作非零判断，通知目标持仓为0，会指派全部空头（源码ProcessAssignmentOrders）。因此合成部分指派通过公开DefaultExerciseModel子类，仅对显式场景tag限制克隆行权单数量，其余交割/事件/资金继续调用官方实现。普通模型和真实接口不变；首次失败日志assignment-native-second.log保留，不把两张全指派当部分指派通过。

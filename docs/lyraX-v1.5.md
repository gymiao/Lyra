# lyraX v1.5：策略工作台与多策略研究计划

日期：2026-10-09（Asia/Shanghai）。设计修订：**R1，实施完成，工程验收见[V1.5交付](V15-DELIVERY.md)**。复核问题及验证场景见[复核记录](lyraX-v1.5-REVIEW.md)。

本计划依据用户要求，将上一轮讨论的策略类型对应到当前 LyraX 的扩展路线。原规划文档保留设计依据；用户追加授权后已实施P0–P5，验收和外部资料边界分别记录。恢复入口：[agents.md](../agents.md)、[进度](PROGRESS.md)。原始 V1 需求见 [GOAL.md](../GOAL.md)。

## 1. 目标与范围

让用户能够在中文页面完成“选择策略模板 → 设置参数 → 检查数据 → 冻结策略版本 → 运行扣费回测 → 对比结果 → 绑定账户版本 → 模拟跟踪 → 人工调仓建议”的完整流程。开发者添加一种策略时，只实现规则及声明依赖，复用数据、时间检查、bt 回测、账户、风险和报告模块。

**当前采用的范围假设**：沿用日线、月度决策、单市场 USD、只做多、无杠杆。用户尚未选择扩大到套利/做空，因此 v1.5 以六类只做多策略的工作台为交付范围；第 12 节列出套利及市场中性的独立扩展条件。不能把这个交付描述成“七类交易策略全部上线”。

| 上轮讨论的类型 | v1.5 交付 | 数据及边界 |
|---|---|---|
| 固定配置与再平衡 | 保留 `fixed`，接入统一模板及编辑器 | ETF 日线，兼容既有结果 |
| 趋势跟随 | 保留 `trend`，均线窗口配置化 | ETF 日线，默认规则仍为 126 日均线 |
| 动量轮动 | 新增 `momentum_rotation` | 按历史收益排名，月度选前 K 名，允许现金 |
| 均值回归 | 新增 `mean_reversion` | 月末价格偏离均线的只做多规则；不承诺日内反转交易 |
| 风险配置 | 新增 `inverse_volatility` | 波动率倒数配置；名称及报告不称其为严格等风险贡献策略 |
| 多因子选股 | 新增 `multi_factor` 与两种数据模式 | 价格因子可直接用于 ETF；价值/质量模式使用带时点的标准因子 CSV，在声明的美股篮子内选股 |
| 套利与市场中性 | 形成独立扩展设计和启动条件 | 涉及双边持仓、融券、保证金等；v1.5 不提供可执行模板 |

v1.5 的必需交付包括六类模板、因子 CSV 接口和时点检查、小型独立因子样例、页面编辑/回测/比较、版本管理及跟踪接入。**真实基本面历史数据尚未取得**：样例验证只能证明工程链路；缺少合格来源时，价值/质量的真实研究与跟踪必须保持受阻，并在交付清单单列。动态全市场股票池、严格风险平价、分钟行情、机器学习和自动参数搜索另行规划。

沿用 pandas / NumPy、bt / ffn、Streamlit、Parquet、SQLite 和 Conda。策略规则属于项目业务代码；不另写回测引擎或绩效指标库，不新增数据库服务、消息队列或大模型运行依赖。版本号是规划名称，实施验收前不修改已安装项目版本或依赖锁。

## 3. 用户操作与页面

保留四个主页面，把“策略研究”扩展为策略工作台，不另建一个前端项目。

| 工作台标签 | 操作 | 必须展示的结果 |
|---|---|---|
| 策略库 | 查看六类模板、克隆既有版本 | 规则说明、参数含义、所需数据、当前资格、版本 |
| 编辑与校验 | 选择篮子、填写参数、保存本地草稿、预检、冻结版本 | 字段错误、预热长度、完整月份、首次决策/成交日和版本差异 |
| 回测 | 选择策略版本、基准、数据版本、区间、资金与成本，显式提交 | 任务编号、运行状态、失败原因及可追溯报告 |
| 对比 | 选择兼容运行或在同一实验运行多策略 | 净值/回撤、收益、波动、费用、换手、现金占比、交易和决策明细 |
| 模拟跟踪 | 选择一个已冻结版本，显式绑定 paper 账户 | 生效月末、当前/待生效版本、信号有效期、计划及检查结果 |

绑定前必须检查原价/公司行动数据资格。仅有当前Yahoo研究行情时，可以保存待生效绑定并查看信号，但状态显示“跟踪受阻：缺少合格执行原价”，不得显示模拟成交链路已就绪。账户页提供标准原价CSV/行动凭据导入入口，导入后重新核验。

典型流程：选择动量轮动模板 → 输入 SPY/IEF/GLD、126 日、前 2 名 → 数据预检 → 冻结版本 → 与固定权重基准回测 → 查看每月入选及未入选原因 → 选择后续月末开始纸面跟踪。

页面表单由注册的参数元数据生成，只支持受控字段，不支持上传可执行 Python、任意表达式或在页面安装插件。保存参数不会自动回测；回测完成不会自动启用账户；页面刷新或切页不会产生新的任务或成交。账户仍只绑定一个当前策略。

运行状态页增加研究任务、数据资格和计划版本冲突；账户/调仓页显示当前绑定版本和信号来源。中文标签同时区分行情来源、研究/模拟/真实用途、截至日期和实际生成时间。收益高低不转换为“适合用户”评级。

## 4. 策略契约、版本和存储

### 4.1 最小接口

| 对象 | 核心字段/能力 |
|---|---|
| `StrategyDefinition` | template_id、implementation_version、中文说明、参数类型/范围、支持市场/周期/用途、required_history、required_datasets、校验及计算函数 |
| `StrategySpec` | schema_version、strategy_id、revision、template_id、implementation_version、parameters、universe_id/hash、基础权重、组合权重政策、数据/日历/发布时间政策引用、spec_hash、创建时间 |
| `DecisionContext` | 决策/适用交易时点、按时点截断的行情与因子、数据质量、交易日历、已知账户状态；v1.5六个模板权重均不依赖实际账户资金/持仓 |
| `DataBundle` | 用途明确的研究价格、执行原价、行动、因子、篮子和日历快照引用；每个引用的哈希、来源、实际取得时间与资格；缺少执行原价不阻断研究 |
| `StrategyDecision` | 目标权重、每标的原因/分数、决策/适用时间、状态、规格版本、输入依据哈希；进入现有 Signal 包装和归档 |
| `ResearchSpec` | 唯一member_id对应精确策略版本，benchmark_member_id、DataBundle、共同开发/验证/评估区间、资金、成本/费用预留政策、成交假设、源码/依赖/引擎适配版本、用途及实验哈希 |

模板声明需要多少个价格或收益观测，不能把 126 个价格误当作 126 个收益。生成权重的函数无账户写入副作用，不自行下载行情或修改现金。公共入口先做月末、数据可用性和完整性检查，再调用规则；新增策略不能绕过它们。

`spec_hash` 覆盖计算规则、模板实现版本、参数、篮子版本、基础权重、权重政策及影响决策的数据/日历/发布时间政策；中文显示名、备注与创建时间不改变计算身份。数据内容使用独立哈希，不和策略身份混在一起。归档额外保存源码指纹、依赖版本和实际生成时间。未知版本明确报错，不能悄悄运行最新版。

### 4.2 身份、读取与配置解析的闭环

以下规则随P0冻结；接口必须接入全部调用入口：

- `template_id`表示规则类型，`strategy_id/revision`表示用户保存的版本，`spec_hash`表示计算内容，`member_id`表示一次实验中的成员。一个实验可同时比较momentum的63日与126日版本，bt名称、净值列、CSV文件和指标字典必须使用唯一member_id；显示名不参与路径拼接。完全重复的同一规格拒绝重复加入，不按模板名称覆盖结果。
- 同一spec_hash可被不同名称的策略引用；内容按哈希去重，策略身份/版本引用单独保存，不能用内容哈希唯一约束阻止用户克隆。重命名只改展示元数据，不改冻结计算内容。
- 引入一个共享解析入口生成 `ResolvedStrategyContext`：legacy配置或精确版本引用二选一。显式新版本与旧lookback/weights/active_strategy等字段冲突时报错；不可悄悄用旧默认值。CLI、UI、research、archive、daily、plan和simulator均使用该解析结果，业务层再次校验。
- 新 `Signal`/归档payload使用显式schema版本和共享解码器。旧v1归档按原字段/哈希验证后适配读取；新信号携带spec_hash、DataBundle引用和资格。更新CLI/UI/daily中直接 `Signal(**payload)` 的调用，不能增加字段后让旧记录无法打开。新接口不把新规格塞进旧config_hash冒充同一种对象。
- 决策内容指纹只涵盖该时点实际使用的规则、价格/因子行及状态；完整下载快照、运行时间与源码属于可追溯引用。追加未来数据可能产生新快照/运行ID，但不得改变既有决策的权重、原因及其内容指纹；既有前向归档始终不可覆盖。
- v1.5六模板是无账户状态的权重规则；`account_state`用于时点核验和后续计划。不支持需要逐步持仓记忆的策略直接接入一次性history预计算，扩展此类策略需另验引擎逐时状态接口。

### 4.3 生命周期与账户绑定

- 草稿可编辑；冻结后内容不可覆盖。修改参数或规则建立新 revision，显示版本差异。
- 模板实现发生变化也增加实现版本；现有归档和报告继续可读。旧实现不可用时显示“仅可查看，不能以当前实现精确重跑”，不伪造复现。
- 账户绑定保存当前 spec_hash、待生效 spec_hash、生效决策交易日、请求时间、绑定序号和操作记录。以该月末收盘+配置发布延迟为版本冻结截止；请求必须早于截止才可用于该次决策，过截止选下一月末。UI显示实际生效日期；不能通过CLI回填早于请求时间的绑定。更改研究策略列表不影响账户。
- 旧计划及其部分成交继续引用旧冻结规格。新版本不能覆盖在途订单、释放旧资源或重新做一份同月意图；未解决占用时新绑定/计划明确阻断。
- 保持当前月度意图键的实际语义：账户 + 环境 + 决策交易日。策略版本属于该意图冻结内容，不能通过换参数/策略制造同月第二个意图。
- 编辑成本或风险参数与编辑策略分别记录；计划修订仍使用现有冻结信号和修订流程。页面选择另一策略不改变实际账本。
- 绑定切换、该月版本选择和信号归属在单写者约束下固定，提交时复核binding_seq及账户账本序号；冲突重新读取，不能两种版本同时“成功”。截止时存在旧未解决计划则记录本次切换受阻，不偷偷沿用旧版本或顺延日期；用户须明确安排新的生效月末。旧在途事实继续按原归属处理。
- 无交易需求也写入月度决策结果`NO_ACTION`及binding/spec引用，不创建空订单。漏跑检查以账户、当月绑定、规格和decision_session核对；同月其他研究版本的READY信号不能掩盖该账户漏跑。

### 4.4 存储方案

沿用各环境的 SQLite，策略配置可以导出为 TOML。schema v3已增加 `strategy_versions`、`strategy_bindings`、`research_experiments`、`research_attempts`及无订单月度结果记录；复用现有tasks做当前状态摘要，不用覆盖式tasks代替不可变attempt历史。策略/版本引用唯一，内容可按spec_hash去重；实验成员、参数、运行与产物均可追溯。P0冻结迁移和引用结构并在临时库验证，P2使用升级后的隔离研究库，P3才迁移实际工作目录并接账户。

Parquet 保留价格，新增 `runtime/<environment>/factors/` 保存因子快照，研究目录保留 manifest、净值、交易、持仓、决策与比较报告。定义具体表结构前确认现有唯一约束和事务边界；具体契约见src/personal_quant/strategies与portfolio/schema.py；篮子身份由规范化symbols及spec_hash表达，公司行动随价格快照引用，不额外引入行动数据库。

## 5. 六类模板的初始规则

以下参数用于工程样例，须在首份新策略研究报告之前冻结，不以回测结果反复修改。新增模板的共同参数：`invested_budget`（闭区间[0,1]）、`weight_cap`（区间(0,1]）、篮子及规则参数。默认新样例预算 0.95、上限 0.60；既有 V1 模板走兼容模式，不偷偷改为 0.95。

所有模板月末收盘后决策，研究于下一交易日收盘模拟成交；之前的价格变动归旧持仓。每日运行仅用于数据和既有计划推进。

| 模板 | 首版规则与参数 | 无持仓/不足情形 |
|---|---|---|
| fixed | 按明确配置的目标权重月度再平衡 | 合法全现金目标允许；显式权重不自动归一化 |
| trend | 复权收盘严格高于最近 lookback 日均价才保留原权重，默认 126 | 被过滤部分留现金；相等时不持有 |
| momentum_rotation | momentum = P(t) / P(t-L) - 1，L=126，需 127 个价格；先按收益降序，再按稳定标的 ID 排序；选最多 K=2 个严格正收益标的 | 每个入选者分配预算/K，少于 K 时空位留现金；都不满足时为有效全现金 |
| mean_reversion | deviation = P(t)/SMA(L)-1，L=20；月末 deviation ≤ -0.05 时持有该标的基础权重，否则为 0 | 次月重新判断，不加入盘中止损或依赖实际账户的隐含持仓记忆；无触发为全现金 |
| inverse_volatility | 使用 L=63 个日简单收益的样本标准差（ddof=1），需 64 个价格；权重与 1/σ 成比例，乘投资预算 | σ 非有限或 ≤ 1e-8 时阻断并说明；不对零波动分配无限权重 |
| multi_factor | 对各因子在篮子中排名，按固定系数合成分数，选择前 K 名，按预算/K 分配 | 数据缺失/超龄与未入选区别显示；因子不足不能填 0 后参与排名 |

权重处理约定：模板先输出原始目标，检查有限、非负、总和不超预算；对有规则性分配的新增模板按上限裁剪，截出的部分留现金，记录原因，不向其他资产二次分配。显式 fixed/trend 配置超限直接校验失败，不能偷偷修改用户输入。最终仍执行账户层风险检查、费用预留、整数单位和资金约束；这些措施会产生与研究权重的偏差。

基础权重与约束补充：mean_reversion的base_weights必须显式配置且总和不超过invested_budget，或显式选择“等权”后按预算/N生成；不能隐式继承旧Config.weights。fixed/trend兼容模式保留原权重与参数，新规格的基础权重同样显式冻结。K为整数且1≤K≤篮子数量；multi_factor要求N≥2；窗口/阈值/排序方式使用模板独立校验。

`weight_cap`是策略输出政策，账户的`max_weight`是执行风险限额。绑定前要求规格声明的最大可能目标不超过账户限额，不满足则保持研究可用、账户绑定受阻，不能在绑定时静默改策略。当前持仓仍需独立核验。研究的策略预算只应用一次，bt费用预留只应用一次，账户现金缓冲只在真实单位计划中约束购买力；报告分别展示这三者，不把费用既计入缩放又再次计作已支付。V1的保守费用预留保留原算法作为独立政策版本；候选与基准使用同一政策，研究与整数计划的偏差继续披露。

表单切换模板时以草稿/模板版本分隔字段状态；隐藏字段不参与提交，服务端拒绝旧模板残留参数。

多因子首版提供两个预设：

- **价格因子**：126 日动量（越大越好）与 63 日波动率（越小越好），系数各 0.5。用于 ETF 或固定股票篮子，不称为价值/质量选股。
- **价值/质量因子**：book_to_market 与 roe_ttm，各 0.5；需要来源已明确的历史时点数据。指标名称、单位、TTM 算法/分母及可用时间随输入记录，不跨来源拼接不同定义。非正账面权益或无有效 ROE 分母为不可用，不能当作极端分数。

因子方向先统一成“越大越好”，再用平均秩处理同分，按 `(rank - 1)/(N - 1)` 转成 0–1 分数；N 必须至少为 2。最终总分相同才按标的 ID 排序。因子系数必须有限、非负、总和为 1，不静默重配缺失因子的系数。首版采用整个声明篮子完整校验，任一必要输入缺失则该决策受阻；以后若支持排除部分标的，必须另行版本化规则。

独立预期样例：

- 动量收益 A=12%、B=8%、C=-2%，预算 0.95、K=2、上限 0.60 → A/B 各 0.475，现金 0.05；只有 A 为正时 A=0.475，余款留现金。
- 反转基础权重各 0.30，偏离 A=-6%、B=-2%、C=+3%，阈值 -5% → 只有 A=0.30；恰好 -5% 也满足。
- 波动率 A=10%、B=20%，预算 0.90 → A=0.60、B=0.30、现金 0.10；若上限 0.50，则 A=0.50、B=0.30、现金 0.20。
- 因子有三只股票：价值秩分 A=1、B=0.5、C=0；质量秩分 A=0、B=0.5、C=1。各半加权后三者均 0.5，按固定 ID 排序选择，输入 CSV 行序不得改变结果。

## 6. 数据资格与基本面闭环

### 6.1 价格、篮子和市场

现有 SPY/IEF/GLD 真实日线可验证价格类模板。价格质量、复权收益、公司行动、收盘可用时点继续沿用 V1。当前 Yahoo `Close` 的供应商拆股调整口径仍不直接作为真实证券数量的原价。

首版篮子固定、显式配置，记录 `universe_id`、成员、生效区间、形成依据和实际记录时间。股票研究先限制为当前明确支持的交易日历/币种及完整历史区间，不把纳斯达克资产机械标成 NYSE。增加其他交易所必须补证券元数据和日历映射验证，不能只改 symbol。

用今天仍存在的股票做历史研究应标为“事后固定篮子，存在存续选择偏差”。要声称时点股票池，必须有该时点的成员凭据及退出/退市处理；上传成员日期不能自动获得此资格。

现有回测要求完整矩形价格矩阵，v1.5 保持这一边界：IPO 前、退市后、停牌或缺价不补成可成交价格，不把缺数据股票悄悄剔除后继续声称原篮子结果。动态全市场成员变更和退市结算作为后续能力，数据不满足时阻断相关研究。

### 6.1a 从研究行情到真实单位计划

DataBundle明确区分`signal_prices`（复权研究）和`execution_quotes`（经核验原价），公司行动另列引用。当前PlanService要求首次计划的signal.snapshot_id等于传入metadata.snapshot_id；新增多来源时必须改成“归档信号及其决策输入已验证 + 独立执行报价已验证”的契约，不得直接删掉旧相等检查而不补验证。

- 计划引用不可变信号归档，权重只来自该归档；执行报价只用于估值、风险及数量，不重新计算排名。报价真实取得时间≤计划生成时间，价格available_at≤估值时间，日期为当时最近完整交易日。
- 两种价格通过稳定asset_id、证券单位、市场/币种和日历映射关联。ticker只是代码，不能因改名或拆股将旧单位套在新价格上。执行数据必须覆盖“目标篮子∪现有持仓∪未完成计划占用标的”。
- 同一证券价格来源差异和拆股转换依据保存为独立证据；无法证明单位一致则阻断。CSV标签写unadjusted本身不等于已经完成来源核验；不推算未经验证的Yahoo历史原价。
- 没有合格原价/行动凭据时，状态为`RESEARCH_ONLY / EXECUTION_DATA_REQUIRED`；页面允许导入标准CSV再预检。demo通过明确的合成原价样例跑通闭环；paper/real必须使用实际来源证据，不能复制合成样例改标签。
- 原价、行动和研究快照均进入计划清单及备份。升级后用独立两来源样例验证“信号不变、数量来自原价”；原同一快照路径继续兼容。

### 6.2 因子 CSV 与历史可用性

新增标准因子 CSV 及元数据模板，规范化为版本化 Parquet。最低字段：asset_id、factor_name、value、unit、period_end、published_at、available_at、value_as_of、source、source_record_id、revision、currency、data_type、definition_version；系统另写recorded_at和来源证据身份；快照保存输入文件哈希、来源说明、取数记录、质量状态。日期时间必须带时区。

- `period_end` 是报表期末，不是市场已知时间。先按available_at≤decision_time及来源有效性过滤，再选择最新合格period_end；在该报告期内选当时已发布的最新修订。后发布的旧季度修订不得覆盖已经存在的新季度。重复身份键至少包括来源、asset_id、factor_name、period_end、definition_version、source_record_id及revision。
- 校验published_at≤available_at≤决策时点，未来value_as_of无效。recorded_at由本机首次接收时写入且不因重复导入刷新，CSV自报时间只作为来源声明；前向使用需记录时间不晚于实际决策。
- 新鲜度分开计算：底层财报按period_end及定义配置max_report_age_days，预计算因子按value_as_of配置max_value_age_sessions/days；不能因导入或修订而把旧财报“变新”。样例财报最长180自然日只是工程参数；book_to_market还依赖市值估值日，必须标明价格/市值依据及其可用时点，不能把季度末比率无限沿用到今天。
- 历史来源在当时发布过、今天才导入的数据可作带说明的历史重建；真正前向信号还要求 recorded_at 不晚于实际决策。最新财务快照不能回填为过去已知。
- 重复行按来源/外部 ID/版本及内容去重，同一身份内容冲突报错；修订保留两个版本。不将缺失值填零或用未来报告回填。
- 合成/测试因子与真实行情组合演示必须整体标为“含测试因子的工程模拟”，不得只展示“真实行情”标签并进入 paper/real 前向跟踪。
- 价值因子的市场价值与账面口径、ROE 的分母及期间必须可解释。若 CSV 提供预计算值，应保留来源定义和证据；格式正确只证明可解析，不能证明数据为真或有使用授权。

完成接口时提供人工构造的小样例验证“财报发布前不能使用、发布后可用、之后修订不改变之前决策”。真实来源另设验收：授权/字段定义核对 → 小批真实样本取得 → 可用时间抽查 → 真实因子研究报告。没有合格来源则记录具体阻塞，先完成六模板的工程工作，不采购数据或把最新财务接口当作历史数据库。

数据资格按策略、用途分别显示：`可回测`、`可前向跟踪`、`可算真实份额`。只通过第一项不能直接获得后两项。

## 7. 多策略回测与研究纪律

1. 一次正式比较明确基准member_id、候选精确版本及相同篮子、价格快照、评估区间、资金、佣金、滑点、固定费、现金利息和成交时点。首版不做跨篮子的直接排名；这些报告只能并列查看并说明差异。资产配置规则本身造成的现金比例差异保留并解释。
2. 各策略声明预热需求，预检整段评估所需决策日，而非仅找到一个双方READY月份。冻结共同月末网格、首个合格决策和下一交易日成交日期；需要调整起点时在提交前明确记录。评估开始时全部从同额现金出发，首次共同成交前的现金区间保留；不为某个候选补做区间前交易。缺少共同合格决策时不可比较。
3. 共用 bt 适配，只把历史权重映射到下一交易日。各成员的初始资金基线及观察区间完全相同，首日费用纳入收益；全现金策略保留有效曲线和空交易表。日历范围延伸到末次月末之后的执行窗口，用已知日历而非未来行情计算日期；区间末信号可以展示，区间外成交不计入收益，不因CALENDAR_RANGE静默漏掉末次决策。
4. 初始版本每次允许基准 + 最多 6 个候选，顺序执行，避免本机资源失控。参数枚举、自动“选冠军”不在范围内；不同费用或区间的旧报告允许并列查看，但标为不可直接排名。
5. 提交实验前冻结开发/验证/最终评估区间及规格。用户已看过的 2024–2026 报告区间不能再声称是新策略未见的独立评估集；这些试验标为探索性。真正新的评估需预先冻结未用于选规则的数据区间或累计后续前向记录。
6. 最终评估被查看后再改规则，形成新实验并记录评估已被观察；不自动转移/隐藏失败或低收益试验。工程验收不以收益为正或超过基准为门槛。
7. 报告保存每次决策的分数、入选/未入选原因、原始及最终目标、现金、约束和输入版本，继续保存实际成交/持仓/费用。模板规则和数据资格可以从报告完整追溯。

### 7.1 阻断状态不得改变策略语义

- 新决策状态区分 `READY`（可以含全零目标）、`INSUFFICIENT_DATA`、`DATA_QUALITY_BLOCKED`、`NOT_REBALANCE_DAY`、`EXPIRED`。仅READY有可执行目标；受阻时新payload的target_weights为空值。兼容旧payload里的零权重时仍先检查status，不能据此清仓。
- 当前bt适配会跳过非READY信号；扩展后不能把中途财报缺失/过期变成“本月保持持仓”的隐含策略。正式实验中任一必要月末受阻则实验状态为`DATA_BLOCKED/INCOMPLETE`，可以保留诊断，禁止发布完整可比结果。未来若支持缺失时继续持有，须另定义独立策略版本。
- 全零目标是有效清仓决定；账户已有资产时应生成合规卖出，账户已为空才为NO_ACTION。非调仓日/数据受阻不会触发同样动作。回测与跟踪对上述状态使用同一解释。
- 所有成员使用预先冻结的完整月份和价格覆盖；一个失败不得仅发布其余成员为“完整六策略比较”。结果包含数据受阻月份、结束时尚未成交信号和剩余持仓。

新增比较清单记录配置差异、基准身份、观察天数、可比状态及原因。绩效继续复用 bt / ffn；研究策略收益与个人入金/XIRR 分开展示。对多策略运行增加版本化 manifest 格式，UI 仍可读取 V1 报告。

## 8. 任务、CLI 与模拟跟踪

### 8.1 执行方式

研究提交先解析全部输入为精确版本，再保存不可变ResearchSpec及attempt记录，由当前Conda解释器的本机CLI进程执行；Streamlit只触发及查询。命令使用固定入口和参数列表，传实验ID，禁止将表单拼成shell命令。沿用SQLite和本地进程锁，每个工作目录最多一个活跃研究attempt；繁忙时明确提示，不悄悄排一个无人管理的队列。

重复点击/刷新/两个浏览器标签通过数据库唯一约束复用同一实验和活跃attempt，不能仅依赖Streamlit会话UUID。experiment_hash包括规范化ResearchSpec、所有输入哈希和源码/依赖/引擎版本；attempt_id单独标识执行，重新运行仍保留每次退出原因。源码或依赖变化必须建立新执行依据，不能声称同一个实验已精确复现。spec显示名变化不新建计算实验。

区分待启动、运行、成功、失败、已中断。先写任务再启动子进程，启动失败留FAILED；进程以事务条件更新取得执行权，重复进程退出。记录workspace、worker令牌、PID、启动标识和系统启动身份；PID存在或心跳超时单独都不足以判定归属/死亡。UI重启而工作进程存活时仅重新连接；锁及执行者确认不存在才标中断，重试需新attempt且不覆盖旧记录。

研究中断只保留诊断，完整manifest校验通过后才进入成功发布。当前tasks表使用UPSERT，仅作为最新摘要；所有attempt保留在专用不可变历史中，状态转换用条件更新防止旧进程覆盖新状态。

下载需显式操作或作为实验明确输入阶段；运行过程中冻结快照，不因在线价格更新而改变实验输入。SQLite 事务不跨越网络下载或 bt 计算。研究工作进程不能写账户资金事件。

### 8.1a 文件、数据库和备份的一致发布

文件rename与SQLite提交无法合成一个事务，按以下顺序设计恢复：

1. 计算写入当前attempt专属pending目录，产物逐项校验哈希。发布前再次确认attempt执行权，账户/研究共同的短时发布锁先于数据库事务获取；网络和bt计算不持有该锁。
2. 完整目录原子发布，再在事务内登记产物引用及成功状态，最后原子更新latest指针。数据库未登记的目录为待恢复产物，UI不得因目录名完整就视为成功；已登记但latest未更新时从成功记录恢复指针。
3. 若任一步中断，恢复先校验experiment/attempt/输入/文件哈希，内容匹配才补齐登记，绝不猜测成功或覆盖同ID不同产物。保存失败或磁盘空间不足保留明确错误和最近成功报告。
4. 备份取得同一发布/账户锁后做SQLite一致快照，只复制该快照可达的已发布文件；pending产物排除。计算进程可以继续准备文件，但须等待发布锁后才登记。
5. 备份使用明确类型的引用解析器，覆盖策略版本、DataBundle的全部快照、因子、绑定、实验成员和报告。当前仅识别snapshot_id/reference_snapshot_id的扫描必须扩展；不能漏因子后仍显示备份成功。旧格式单独解码，恢复到新空目录验证全部引用及状态。

### 8.3 前向与实际账户

历史研究和跟踪调用同一模板及规格；跟踪按每个月冻结的binding/spec选择信号，不能查到同月任一READY研究信号就认定该账户已完成。paper/real使用系统实际时钟、冻结前向数据，月末漏跑保留缺口，不将新历史报告作为已发生的前向信号。现有资金入出、结算、分红、整数单位、对账及资源预留规则继续约束新模板。

模拟账户使用事前计划数量与已有次日收盘成交假设，不能在成交后按新价格重选排名或数量。目标以外的现有持仓仍须纳入减仓和报价检查。没有合格原价/公司行动数据时可研究，但证券份额模拟或真实计划受阻。

各策略可在独立工作目录分别纸面观察；同一环境仍只有一个账户及一个启用策略，不在本版本增加共享账户的多策略资金分账。已有真实空账户不自动注入示例资金。

## 9. 兼容、迁移与恢复

- 平铺 schema v1 配置走兼容适配，原 fixed/trend 的规则、默认数据窗口及成本保持原意。旧配置内容哈希及已归档标识保留；新增规范化规格保存与原配置的映射，不能重算并替换旧历史身份。
- 新规格解析未知键、NaN/Inf、非法权重、非整数窗口、K 越界、无支持市场时直接报错；不能靠 UI 校验代替 CLI/业务层校验。

## 12. 套利、市场中性及后续边界

上述第七类策略需要新的经济和账户语义，不能只允许目标权重为负。后续版本需单独设计并验证：

1. 明确策略子类：股票配对、期现或其他价差；确认工具/市场/币种和交易日历。同期权等不同行权或结算方式的工具不能共用未经验证的简单份额逻辑。
2. 数据：两腿同步且可成交的价格、融券可得性与借券费、保证金及融资条件；涉及期货时还需乘数、到期、换月和结算记录。日线价差研究不能证明盘中套利可成交。
3. 账户：空头持仓、借券负债、空头分红义务、资金及保证金、强平/召回处理。重新定义权益、购买力和风险；不得套用当前只做多账本。
4. 执行与研究：双腿下单顺序、只成交一腿的风险、部分成交、滑点、持仓限额和退出条件；先验证可复现的研究及模拟故障场景，再考虑自动执行。
5. 框架：出现上述需求时单独核对 bt 的适用边界；券商自动交易仍按 V2 条件评估成熟适配器。未经比较和验证，不为 v1.5 同时引入多个主回测框架。

严格等风险贡献配置也另列扩展：需要协方差估计、求解与收敛验证；当前波动率倒数仅交付它实际实现的规则。

启动这些扩展需要用户明确具体策略、市场、券商/数据权限及开发范围；任何自动下单仍需要独立授权。
